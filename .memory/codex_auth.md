# Codex auth

- `selectCodexAuth` in `utils/codexHome.ts` must `delete process.env[slot]` for every `CODEX_AUTH_JSON_<N>` after it copies the chosen slot into `CODEX_AUTH_JSON`, because `agents/opencode.ts` spawns with `...process.env` and `agents/codex.ts` and `mcp/shell.ts` pass raw `process.env` when `payload.shell === "enabled"`, so `filterEnv()` does not stop a leftover slot from reaching the agent; a new multi-slot credential family needs the same delete [source: https://github.com/anaclumos/pullfrog/pull/1]
- An `OAuthWriteback.secretName` must come from the `installCodexAuth()` or `installCodexHome()` return value, never the literal `CODEX_AUTH_JSON`, because after slot selection `CODEX_AUTH_JSON` holds the chosen slot's chain and a literal name makes the post hook overwrite the primary while the chosen slot keeps a dead refresh token [source: https://github.com/anaclumos/pullfrog/pull/1]
- `SUBSCRIPTION_SECRET_NAMES` in `commands/_shared.ts` matches exact names and does not contain `CODEX_AUTH_JSON_<N>`, so a shadow guard that only calls `.includes(name)` skips extra Codex slots: also test ``name.startsWith(`${CODEX_AUTH_SECRET}_`)`` as `commands/secret.ts` does [source: https://github.com/anaclumos/pullfrog/pull/1]
- `probeCodexQuota` sends the stored `tokens.access_token` as is and maps every non-2xx response to `unknown`: never refresh the token in the probe, because the refresh chain is one-shot and every probed slot would then need its rotated chain written back [source: https://github.com/anaclumos/pullfrog/pull/1]
